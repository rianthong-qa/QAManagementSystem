UX/UI Development Specification

รายละเอียดสำหรับนำดีไซน์นี้ไปพัฒนาใน ProMaxx2 QA Hub

1. Visual Hierarchy

  • หัวหน้าหน้า + Primary Action ต้องเห็นก่อน KPI
  • KPI ใช้สำหรับ Summary เท่านั้น ไม่ใส่รายละเอียดเชิงลึก
  • Workflow แสดงเป็นเส้นทาง 5 ขั้นตอน ไม่ใช้ Card ซ้ำหลายชั้น
  • Action Required ใช้สีสถานะเพื่อบอกความเร่งด่วน
  • Recent Execution เป็นส่วนหลักด้านล่างสำหรับงานประจำวันของ QA

2. Design Tokens

  • Primary: #2563EB
  • Success: #16A34A
  • Warning: #F59E0B
  • Danger: #DC2626
  • Surface: #FFFFFF / Background: #F6F8FC
  • Border: #E2E8F0
  • Radius หลัก: 12–16px
Primary Action Status Color Soft Background Neutral Border

3. Component Structure

  • AutomationPageHeader
  • AutomationMetricCard
  • AutomationWorkflow
  • AutomationActionList
  • AgentStatusCard
  • AutomationExecutionTable
  • StatusBadge / EmptyState / LoadingState

4. Responsive Rules

  • ≥1280px: KPI 6 Columns, Action + Agent 2 Columns
  • 900–1279px: KPI 3 Columns, Section อื่นเรียง 1 Column
  • <900px: ซ่อน Sidebar และใช้ Drawer/Menu
  • <560px: KPI 1 Column และ Table ใช้ Horizontal Scroll

5. Interaction

  • กด KPI → ไปหน้ารายการที่ Filter ตามสถานะ
  • กด Workflow Step → ไปหน้า Stage ที่เกี่ยวข้อง
  • กด Action Required → เปิดรายการ Maintenance / Failed / Ready
  • กด Agent → เปิด Agent Detail / Heartbeat / Capability
  • กด Row Action → View Detail / Evidence / Re-run / Create Defect

6. Status & State

StateUIBehavior
ReadyGreenRun ได้
RunningPurple/BlueDisable duplicate run
MaintenanceOrangeบังคับ Review DSL/Object
FailedRedเปิด Evidence/Defect Action
Agent OfflineGray/RedDisable Run

7. API/Data Mapping

  • KPI: GET /api/automation/dashboard/summary
  • Actions: GET /api/automation/dashboard/actions
  • Agent: GET /api/automation/agents/status
  • Recent Runs: GET /api/automation/executions?limit=5
  • Create Case: POST /api/automation/cases

8. UX Acceptance Criteria

  • ผู้ใช้รู้ได้ภายใน 5 วินาทีว่ามี Case/Fail/Agent เท่าไร
  • Action ที่ต้องทำต้องมองเห็นโดยไม่ Scroll บน Desktop
  • Primary Action “สร้าง Automation Case” ต้องเห็นชัดที่สุด
  • สีต้องไม่เป็นตัวสื่อสถานะเพียงอย่างเดียว ต้องมี Label
  • Table ต้องรองรับ Loading, Empty, Error และ Pagination
